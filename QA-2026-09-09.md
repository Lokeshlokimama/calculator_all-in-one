# Website QA — 9 September 2026

## Scope

- Inspected all 40 sitemap pages in the browser at 375×812 and 1280×600. Checks covered main headings and viewport bounds of primary inputs, selects, buttons and navigation. These are layout checks, not exhaustive functional tests of every tool.
- Checked all 58 public HTML files with the static checker: local links/anchors, titles, metadata, JSON-LD, sitemap membership and redirects.
- Browser-tested invoice totals, invalid-value feedback/recovery, export blocking, zero percentage, negative BMR measurements, excessive SIP duration, impossible attendance targets, and future birth dates.
- Expanded all-page layout checks to 320px, 768px and 1920px widths. Checked homepage/invoice layouts at nine viewport sizes from 320×568 through 1920×1080, including the navigation breakpoint.
- Regression matrices cover 456 password configurations, 6,625 attendance combinations, 60 loan scenarios and 1,560 candidate calendar dates (8,701 combinations total), plus PDF/image upload limits and other boundary cases.
- Existing PDF and financial regression tests remain part of the suite. No claim is made that every file format, browser, external API, assistive technology, or possible input has been tested.

## Issues corrected

1. Mobile invoice editor: its fixed 330px grid minimum clipped fields and actions. The minimum now respects available width.
2. Percentage, GST, leave and tip: legitimate zero values are accepted where meaningful; invalid/non-finite inputs are rejected.
3. BMR, water, protein, body-fat, ideal-weight, BMI and geometry: reject negative, non-finite or overflowing measurements instead of publishing nonsensical results.
4. EMI: stable near-zero-interest arithmetic, whole-month validation, bounded tenure, and overflow checks.
5. SIP and FD: bounded rates/durations prevent excessive chart loops; overflow is rejected. SIP uses stable near-zero-rate arithmetic on both homepage and standalone page.
6. Age: future/invalid dates are rejected. Calendar anniversaries clamp to the last day of shorter months, preventing negative day counts. Standalone and homepage use the same convention; total days use calendar dates rather than elapsed local hours.
7. Attendance: replaced potentially unbounded loops with direct arithmetic. An unreachable exact 100% target has a clear explanation; invalid targets/counts are rejected.
8. CGPA: zero grades count toward the average. Incomplete rows, negative credits and grades outside 0–10 no longer disappear silently.
9. Tip: fractional people are rejected rather than silently rounded down.
10. Time: blank-only, negative, fractional and out-of-range minute inputs receive an error; subtraction can still return a negative duration.
11. Invoice: negative/non-finite values and out-of-range percentages display an error and block export. A sample with 2×100, 10% discount and 18% tax returns 212.40.
12. Asset versions refreshed so a future deployment requests the updated shared CSS and JavaScript.
13. Math and Geometry category deep links now apply their filter on initial load instead of showing every tool. The invoice deep link was verified in a fresh tab.
14. PDF tool navigation stays compact below 960px, preventing the long password-helper title from clipping the Generate link at tablet widths.

## Final result

Build, lint and all 30 regression tests passed. Post-fix browser sweeps reported no console errors or clipped primary controls in the checked layouts. The repaired invoice controls also fit within a 320px viewport. This release is prepared for the user-requested GitHub publication; deployment verification is a separate post-push check.

Viewport checks used the in-app browser, not a physical-device lab. Safari, Firefox, assistive technologies and every possible input/device combination have not been exhaustively tested.

## Reproduce

Run `npm run verify`, then `npm run serve`. Use the local preview at http://127.0.0.1:4173/.

Check the invoice at `/#calc-invoice` on a 375px-wide viewport. Check attendance with total 100, attended 70, target 100; it must explain why exact 100% is unreachable without hanging. Check 0% of 100 returns 0.00 and a future birth date shows an error.

The mobile shortcut/category rows intentionally scroll horizontally. They are not treated as viewport-overflow defects. Passing these checks is not certification of accessibility, legal compliance, or AdSense approval. This audit does not submit an AdSense review.
