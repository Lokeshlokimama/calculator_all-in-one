# Reserved advertising spaces

The public build reserves 63 in-flow spaces across all 42 indexable content pages. Every content page has an end-of-content placement; the homepage and 20 extended guides each have a second placement. Error, compatibility-redirect and verification pages are excluded.

| Placement | Pages | Mount |
|---|---|---|
| End of content | All 42 content pages | `#ad-content-end` |
| After featured section | Homepage | `#ad-after-featured` |
| Between existing explanation and extended guide | 20 expanded guide pages | `#ad-between-guides` |

Each space uses the visible label “Advertisements”, has its own explicit-width container, and stays in the normal document flow. Mounts reserve at least 90 px of height on desktop and 250 px on narrow screens. These are layout reservations, not an ad-size guarantee or a performance measurement with actual ads. A served unit can require additional height; it should expand rather than be clipped. No placement sits inside a calculator form, result, QR image, upload panel, or download control.

## Where the eventual code belongs

The empty `.publisher-ad-mount` elements identify where an approved display-unit snippet belongs. Markup is generated by `adSpace()` in `scripts/build-ad-spaces.cjs`; maintain future integration there rather than editing a generated page that the next build will overwrite. Shared sizing is in `ad-spaces.css`.

Ad delivery remains disabled. This change creates spaces only and contains no invented ad-unit IDs. The repository currently strips and rejects active ad loaders, so simply pasting a live snippet into an HTML output is not an activation workflow. Enabling delivery is a separate integration requiring the actual unit IDs/snippet, a one-time loader, appropriate consent handling and updated disclosures/checks. The publisher verification tag and ads.txt already exist.

On short policy, contact and directory pages, a reserved container does not establish that ad serving on that page is appropriate. Review the actual content and publisher policies when deciding which mounts to activate; unused placements can be removed or collapsed in a future delivery integration. They are not sticky, pop-up or click-to-unlock units.

Placement references: [Google ad placement policies](https://support.google.com/adsense/answer/1346295) and [responsive display behaviour](https://support.google.com/adsense/answer/9183362). Reserved geometry is designed to separate ads from interactive controls and reduce movement; real-ad performance and policy compliance need verification after an actual integration.

## Verification

All 42 content pages were checked at 320 px and 1440 px (84 browser checks): no horizontal overflow, all mounts met their reserved heights, and no placement was nested inside a form or interactive tool panel. A second build retained 63 spaces without duplicates. Build, internal-link checks, article-length checks and all 72 automated tests passed. Actual served ads have not been tested.
